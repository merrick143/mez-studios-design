## Column rules

| Column | Rule |
|---|---|
| **Slug** | Lowercase, hyphenated, source first then surface. Matches the folder name exactly. No dates. Final once the row lands. |
| **Source** | The exact URL studied, or the absolute path of the screenshot supplied. Not a homepage when a section was studied. |
| **Provided by** | `Olli, screenshot` or `agent capture`. Screenshots Olli sends are the highest-value input in the system and are marked as such. |
| **Studied** | ISO `YYYY-MM-DD` of the session that produced the folder. Never backdated. |
| **Question it answers** | One sentence naming a specific design question. "How a 3-weight type system carries five hierarchy levels without a serif" is an answer. "Nice typography" is not. |
| **Risk** | `Low`, `Medium` or `High` plus a clause naming the exact element at risk. |

## Retired and anti-references

A study of something that **failed** is worth keeping. Mark its risk column `anti-reference` and use
section 5 of the template to record precisely what went wrong. Negative design data is not clutter;
the Product Card rejection trail is one of the most useful assets in this repository.
