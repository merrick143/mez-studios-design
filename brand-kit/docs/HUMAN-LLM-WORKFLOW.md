# Human and LLM workflow

## Goal

Use human taste where judgment is expensive and agent effort where work is repeatable. Olli should shape identity and select promoted directions; agents should make those decisions concrete, testable, portable, and hard to misuse.

## Agent-owned work

- Inventory and source reconciliation.
- Reference capture and measurable comparison.
- Candidate generation from approved inputs.
- Token, schema, asset, component, documentation, and release generation.
- Responsive, accessibility, contrast, fallback, provenance, and drift checks.
- Clear review plates and output receipts.

## Human-owned gates

- Identity direction and recognisable character.
- Product name, mark, and gradient assignments.
- Foundation character when several valid options exist.
- Expression-family promotion.
- Golden-output promotion.
- Public release and expensive-to-reverse exceptions.

## Review packet standard

A review packet must show a realistic output at useful scale, name the exact decision being requested, keep copy and product context stable, expose desktop and mobile where relevant, include the closest approved references, and allow select, edit, or reject with a note.

Do not ask Olli to approve abstract variables from a rushed or visibly poor composition. Do not combine typography, controls, layout, colour, imagery, and product-expression decisions when each deserves an isolated calibration.

## Decision lifecycle

1. Research or candidate: no production authority.
2. Human decision: select, edit, reject, or reopen.
3. Approved decision record: stable ID, scope, evidence, owner, and date.
4. Canonical implementation: source data and generated outputs updated together.
5. Validation: machine checks plus required visual review.
6. Release: version, manifest, migration notes, and consumer visibility.

## Fresh-session handoff

At the end of a task, update `CURRENT-STATE.md` and `ROADMAP.md`, record decisions, produce an output receipt, and leave the working tree clean or explicitly explain remaining changes. A fresh session must be able to identify the next task without reading chat history.
